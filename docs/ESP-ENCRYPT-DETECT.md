# 加密类型识别方法论（判别决策树）

> 2026-08-18 调研整理。来源：TrueSight《加密内存数据逆向分析指南》、CE/GG 社区（加密类型扫描、What accesses/writes）、按键精灵内存插件教程（XOR/乘加判别）、腾讯云/CSDN（现象层信号）。
> 定位：ESP-COORD-ANTI.md 的配套方法论——**拿到疑似加密数据后，按本决策树一步步判定它到底是哪种加密**。

---

## 一、识别前：先确认"是否真的被加密"（现象层）

传统数值扫描失败有三种可能，先分清是哪一种：

| 现象 | 判定 |
|---|---|
| 内存字节与界面显示值**无直接映射**（精确搜明文 0 命中） | **加密/变换存储**（本文主题） |
| 数值可见但**存储地址极短周期漂移**（指针链转移） | **动态地址**（走指针链/AOB，不是加密问题） |
| 修改后**立即被还原或崩溃** | **完整性校验**（改前需先定位校验函数/关校验） |
| 精确搜索命中但**改不动**（游戏立即覆盖回原值） | **双副本 + 写回校验**（HCR 金币案例） |

> 快速自检：值域是否异常？附近是否有伴生 key 字段？多次读同地址值是否变化？——任一命中即进入下一步。

## 二、黄金数据：制造多组 (明文 V, 密文 E) 样本

**判别加密类型的前提是拿到 ≥3 组"明文-密文对"**：

1. 让目标数值变化 ≥3 次（每次变化量不同，如 +35 / -75000 / +60）
2. 每次变化后记录：
   - **V** = 界面显示值（明文）
   - **E** = 内存中对应地址的值（候选密文，用模糊搜索或断点定位）
   - **addr** = 该地址（确认是否每次相同 → 判别动态漂移）
   - **t** = 采样时刻（判别时间相关 key）
3. 样本记录格式（可直接喂给脚本）：
   ```
   V1=35,  E1=0x..., addr=0x..., t=1000
   V2=60,  E2=0x..., addr=0x..., t=2000
   V3=175, E3=0x..., addr=0x..., t=3000
   ```

> 找不到密文地址怎么办？→ 走第五章代码层（断点 What writes 直接拿加密函数），比盲搜快。

## 三、数学判别法（对样本做统计建模）

### 3.1 XOR 判别（最常用，先试）

```
取两对样本：K1 = V1 ^ E1，K2 = V2 ^ E2
K1 == K2  → 恒定 key XOR（key = K1），用 K1 解密：V = E ^ K1
K1 != K2  → 动态 key，进入 3.3
```

**低字节不变性速查**（单样本即可初判）：
- XOR 加密下 `E & 0xFF` 与 `V & 0xFF` 的差恒定（低字节只被低字节 key 影响）
- 观察 E 的十六进制：若 E 的**高字节与 V 无关但低字节与 V 线性** → XOR

**变体**：E = V ^ K ^ addr（地址参与）→ 同 V 不同 addr 时 E 不同，但 `E ^ addr` 恒定 → 地址相关 XOR。

### 3.2 乘加/线性判别（定标、隐式变换）

```
假设 E = V * A + B
用两对样本解 A、B：
  A = (E2 - E1) / (V2 - V1)
  B = E1 - V1 * A
用第三对验证：E3 == V3 * A + B？
```

| 结果 | 判定 |
|---|---|
| A=1, B=0 | 明文（未加密，纯巧合） |
| A=1, B≠0 | **加偏移**（V + B） |
| A≠1, B=0 | **纯定标**（V × A，如 ×100 存分） |
| A≠1, B≠0 | **乘加混淆**（E = V*A + B） |

> 实操：把 3+ 组 (V, E) 丢进 Python 做线性回归，R²≈1 即线性加密（A/B 即参数）；R² 差 → XOR 或自定义。

### 3.3 动态 key 判别（地址/时间相关）

```
K1 != K2 且无线性关系 → key 在变。进一步分：
  - K 随 addr 变（同 V 换地址 E 变）    → 地址相关（Warzone 型：key=f(addr, seed)）
  - K 随时间/访问次数变（同地址多次读值变）→ 重加密（key1→key2 轮换）
  - K 完全随机                   → 真随机（无建模价值，走代码层）
```

**判别技巧**：对同一地址连续读 5 次，若 E 变化 → 重加密/动态 key；若恒定 → key 静态。

### 3.4 查表/自定义算法（数学建模失败时）

- 样本间无 XOR 也无线性关系 → S-Box 查表、位混淆、自定义流加密
- **不再猜算法**，直接进第五章代码层（反汇编看实现，复刻）

## 四、地址语义判别（动态漂移 / 伴生 key / 影子）

配合第三章，从"地址关系"补判：

| 观察 | 判定 |
|---|---|
| 每次采样 addr 相同 | 静态存储（加密值本体） |
| addr 周期漂移 | 动态分配（配合指针链，与加密无关） |
| 密文旁 +4/+8 有"疑似 key"字段（非坐标值） | 地址相关加密（key 伴生存储） |
| 同一值存在多份副本，只有一份随操作变 | 影子矩阵（再正交验证选真） |
| 数据与网络包同步变化，本地无稳定明文 | 服务端加密下发（McDota 路线） |
| 数值过于完美/领先一步/带隐藏标记 | 蜜罐假数据（自保：交叉验证再信） |

## 五、代码层裁决（断点 + 反汇编，最终确认）

数学判别只能"猜类型"，**代码层是最终裁决**（还能直接拿算法实现）：

```
① 断点：gg_watch_set 候选地址（全线程，type=2 写 / type=3 读写）
② 操作：让数值变化（触发写入）
③ 命中：poll 拿命中 PC
④ 反汇编：disassemble 命中 PC 前后 20 条
⑤ 读侧/写侧判定：
     写入指令前有 xor/add/mul 链  → 写侧加密（存密文）
     读取指令后有对称解密序列    → 读侧解密（读明文）
     直接 mov 无算术链          → 未加密（前面判断错了，重查）
⑥ 复刻：把算术链翻译成解密函数，外部实现
```

**样例**（社区实例）：
```
mov eax, [ebx+10]      ; 读密文
xor eax, 0x12345678    ; 解密
mov [player_gold], eax ; 明文进显示变量
→ 应搜 [ebx+10] 的密文，解密 = E ^ 0x12345678
```

## 六、快速判别表（实战速查）

| 现象（操作后观察） | 判定 | 处理 |
|---|---|---|
| 改密文 → 游戏值 = 密文 ^ 常数 | XOR（恒定 key） | `xor_search.py` 锁 key / 直接解密 |
| 改密文 → 游戏值 = 密文 × A + B | 乘加/定标 | 线性回归解 A/B |
| 同地址多次读值不同 | 动态 key / 重加密 | 断点反汇编拿 key 生成逻辑 |
| 密文旁有伴生 key 字段 | 地址相关（Warzone 型） | 读三元组 (value, addr, key) 复刻 |
| 值域异常但线性 | 定标/隐式变换 | 归一化还原 |
| 多副本只有一变 | 影子矩阵 | 正交验证选真 |
| 改密文立即还原/崩溃 | 完整性校验 | 先破校验（另一课题） |
| 数值太完美 | 蜜罐 | 交叉验证，别信 |
| 反汇编无算术链 | 未加密 | 直接读（检查前面步骤是否有误） |

## 七、适配 GG-Ghost（脚本化判别）

| 判别步骤 | 用我们什么 |
|---|---|
| 收集 (V, E) 样本 | `gg_search` 模糊/精确 + `value_track.py` 自动采样 |
| XOR/乘加/线性建模 | 新脚本 `enc_id.py`（喂样本 → 自动跑 3.1/3.2/3.3 判别） |
| 动态 key 判别 | 同地址连续读 5 次（`gg_read` 循环） |
| 伴生 key / 影子 | `gg_view_memory` 上下文 + `memdiff.py` 对比副本 |
| 代码层裁决 | `gg_watch_set`（全线程断点）+ `gg_disassemble` |

> `enc_id.py` 计划：输入 `V1 E1 V2 E2 V3 E3` → 输出判别结论（XOR key / A,B / 动态 / 自定义）+ 解密函数代码生成。
